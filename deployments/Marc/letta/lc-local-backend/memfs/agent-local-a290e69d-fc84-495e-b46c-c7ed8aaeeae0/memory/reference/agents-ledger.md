## HOW TO WIRE AGENTS THAT TALK TO EACH OTHER (recurring procedure)
Deploying a pair (or any agents that must message each other) is TWO steps, never one:

1. **Deploy each agent** with its `up.sh --<name>` (Hermes or Letta as usual).
2. **Wire the relay separately — BOTH directions.** Hermes agents are invisible to Letta's `messaging-agents` (not in the Letta registry); a Letta planner reaches its Hermes engineer through the host bridge, and the engineer reaches back via the `letta` CLI. See [[make-agents-talk]] for the full recipe.

### The canonical way (SUPERSEDED 2026-09-08)
Earlier rule ("ALWAYS use `talk.sh`; the `-Q` one-shot was flaky and abandoned") is **stale**. The `-Q --query-file -` failure was the 120s stream timeout, not a fundamental relay defect. The now-canonical one-shot is `hermes -z '...'` with the `HERMES_*_TIMEOUT=inf` (or `=600` for a bounded 10-min call) env vars — see [[make-agents-talk]]. `talk.sh` is fine for a *human* driving an interactive TUI on the host, but it is NOT how pod-to-pod messaging works.

`talk.sh` runs `kubectl exec -it deploy/sudo-<name> -- hermes`, so it needs host-side `kubectl` + a TTY, and runs ON THE HOST (a caller reaches the host first via the nsenter bridge, then runs `talk.sh`).
